Simulation of a Hospital Emergency Department Queuing System 
 
Project Members: 3-4 members (within the same tutorial class) 
Deadline To Submit: 22 June 2026, 23:59 (Week 13)  
Presentation, Q&A: 15 minutes per group, physical presentation. 
 
1. Background 
In a hospital emergency department, patients arrive randomly and wait to be treated by 
doctors. During busy periods, long waiting times may occur. The hospital aims to evaluate 
and improve its service system using simulation modelling. 
 
2. Objective 
This assignment aims to enable students to: 
• Apply fundamental queuing theory concepts in the development of a simulation 
model  
• Develop and implement a functional simulation using Octave or FreeMat  
• Analyse system performance using relevant performance metrics  
• Propose and justify system improvements based on simulation results 
 
3. General Requirements 
Students must: 
• Build a working simulation model using Octave or FreeMat  
• Define and justify arrival and service processes  
• Implement an appropriate queue structure (single-server, multi-server, or priority)  
• Compute key performance metrics  
• Compare at least one improvement scenario 
 
4. Performance Metrics 
Students must compute and analyse: 
• Average waiting time  
• Average queue length  
• Doctor utilization  
• Total patients served

6. Assessment Rubric (Scale 1–4) 
 
6.1 Simulation Model (12 marks) 
Component A: Model Design & Implementation (4 marks) 
Level Description 
4 (Excellent) Implements a priority queue model with multiple doctors. Correct priority 
handling and queue logic. Fully functional and stable. 
3 (Good) Implements a multi-server model (M/M/c) with 2–3 doctors and FIFO 
queue. Model is functional and supports scenario comparison. 
2 (Satisfactory) Implements a basic single-server model (M/M/1) with FIFO queue, 
random arrivals, and service times. 
1 (Poor) Simulation is incomplete, incorrect, or not functioning. 
 
Component B: Arrival and Service Modelling (4 marks) 
Level Description 
4 (Excellent) 
Clearly defines and applies appropriate arrival and service processes (e.g., 
Poisson arrivals, exponential service times or justified alternatives). 
Parameters are realistic and well-justified (e.g., peak vs non-peak rates). 
Demonstrates clear understanding of how assumptions affect system 
behaviour. 
3 (Good) Uses appropriate arrival and service distributions with reasonable parameter 
values. Some justification provided, but explanation lacks depth. 
2 
(Satisfactory) 
Uses basic or arbitrary random data generation with minimal or unclear 
assumptions. Limited justification. 
1 (Poor) Arrival and service processes are incorrect, missing, or not aligned with 
queuing concepts. No clear assumptions.
